# V2.3 Cadence Authority Guarded Scan Callback Integration

Approved 2026-10-13. R3 local-only source and disposable fixtures. Baselines: uploader `58989ca`, dashboard `65d254d`. No real authority activation, production dispatch or rollback execution.

## Reviewed Boundary And Plan

Add an explicitly constructed, **disabled-by-default** dispatcher over the existing schema-2 store. Its trusted local context reader supplies only a current enrollment binding and boolean scan permission; this dependency is internal code, never a request, status payload or execution-capability field. No production policy/activation provider is installed. A future approved factory must derive it from current client-local enrollment/settings and a separately reviewed runtime-mode opt-in. Existing evidence flags remain false; hashes and model enablement are not execution authorization.

For one wake-up: read strict current authority/context, generate a fresh internal UUID and request consistency hash, atomically claim then start, recheck current context/owner/revision/due/lease immediately before the callback, invoke once, validate the existing scan-and-queue result, recheck context, and atomically complete/advance due. An exact duplicate/observed claim never starts or resumes a callback. A context change after claim leaves the never-started claim protected for explicit inspection/cancellation. After a durable start, callback failure/throw, invalid result, lease expiry, invalidation or failed completion preserves started/recovery-required uncertainty and never retries automatically. Recovery-marker failure leaves started evidence protected and returns a distinct generic error.

Cron accepts optional explicit dispatcher injection. If supplied, guarded failure never falls back to the unguarded legacy scan. Otherwise the default production path, hooks, scheduling, logging, scan behavior and public void-return contract remain unchanged. The existing callback body is extracted only to return its scan result to the guarded path. Plugin construction remains unchanged; there is no activation setter, new option/table/schema, route, filter, settings or credential change.
