## Scope and Isolation

The existing developer-only `scripts/tests/lifecycle-local-proof.php` now requires explicit `--provenance` selection for the closed checkpoint. Default lifecycle and `--ledger` cases remain separate and unchanged. Five cohesive helpers hold process barriers, core cases/read-only user audits, race/restart cases, capacity/uncertainty cases and injected request ports. CI performs their syntax checks only; it cannot run the LocalWP database proof. No production include, factory, endpoint, settings, version, dependency, generated asset or existing unit-test expectation changes.

Root realpath, LocalWP metadata, database host/port/name, exact siteurl and persistent-cache rejection precede fixture creation. A random `wp_alynt_lifecycle_probe_` identifier is proven absent before cloning only the empty actual options-table structure. Only that table receives an owner marker and synthetic state/barrier rows. The parent verifies ownership before changing its in-process `$wpdb->options`; independent children receive exact table/token scope and bounded allowlisted scenarios. Children use `SHORTINIT`/`DISABLE_WP_CRON` and no production plugin bootstrap. Only parent-owned children can be terminated; barriers/joins are bounded to 15 seconds. Parent cleanup previews row count, drops only its previously absent/created table, restores the actual table pointer and proves fixture absence even on a proof failure.

Actual options are read-only hashed before/after, covering cron and activation. The provenance selector additionally hashes actual users and usermeta read-only, emitting neither private fields nor per-row hashes. No actual users, roles, sessions, options, cron, permissions or safety row is created or modified. Synthetic schema-4 grant evidence is explicitly untrusted archived input, never an authenticated grant or execution permit. All authorization/nonce ports remain labeled MOCK: real SQL is used for closed context/receipt observation and disabled command denial, not real WordPress authentication.

## Focused Review and Limits

Review separates physical SQL durability from model admission and actual authorization. Query-count assertions include no hidden extra successor write; barrier races use original submitted epochs; read-only transaction failures are rolled back before fixture reseeding; interrupted acknowledgements are not converted into success. SQL values are prepared and identifiers/child arguments fixed or allowlisted. Private state, nonces and user fields are not printed or persisted. Existing lifecycle/ledger case logic, production readers/constructors, PHPUnit assertions/skips and dependency versions remain untouched.

This proves fixture-table SQL/process/local-cache behavior only. It does not prove real sessions/capabilities/nonces, authenticated provenance issuance, persistent object cache, power-loss durability, cooperating production providers/writers, settings/connection ABA, after-start queue/upload effects, downgrade/uninstall/handoff or active lifecycle. No full feature/pre-release certification, package/release/deploy, actual migration, authority activation or rollback execution is claimed. Versions remain uploader `0.5.25`, dashboard `0.1.77`.

Restore-point check used the clean uploader baseline and toolkit external snapshot root; no new checkpoint/archive, site/database backup or rollback was made. Local regression/QA and exact-commit publication evidence follow only after execution.
