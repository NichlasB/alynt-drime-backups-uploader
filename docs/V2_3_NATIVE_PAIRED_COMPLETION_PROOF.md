## Implementation

The existing final dormant owner adds two cohesive private traits. Construction
is still zero-IO, zero-argument, test-loaded/unregistered; public methods remain
only creation/privacy/disposition. There is no public execute/request/SQL/provider
port, returned handle, permission Boolean, new REST/AJAX/cron route or loader.
Public storage/admission/dispatch/execution support remains false. Private/final
visibility is not a sandbox against malicious same-process PHP/reflection.

After acknowledged closed-begin commit, exact two-row readback, renewed genuine
core authorization and acknowledged owned close, the owner alone mints private
continuation facts. They pin the original command, post-begin tuples, actor,
cookie, borrowed authentication handle/facts and original wall/monotonic budget.
No caller can supply a completion UUID, timestamp, connection or proposed bytes.
The original begin reserves the completion identity once; it is never renewed.
Private disable immediately consumes this continuation; complete invalidates it
before authorization/IO, including refusal. No public array or fixture capability
is admitted. One-shot owner reuse is refused, not a durable cross-request registry.

Completion opens a fresh exclusively owned native connection under the existing
MariaDB candidate profile. The borrowed WordPress connection is only passively
fenced, never configured, committed, rolled back, closed or reconnected. Both
rows in each pair transaction use the **same** private physical session.
Completion compares the exact confirmed **post-begin** tuples, then prepares the
full model completion and exact serialized one-token patch outside locks. It
retains the original ten-second total flow budget and original UTC expiry; its
candidate timestamp is prepared once. Legacy validators can invoke WordPress
hooks and therefore never run in the native critical section.

After the final genuine guard, the pair locks safety first, verifies schema and
metadata under MDL, then locks settings. It compares complete validated tuples,
including row IDs/autoload/raw bytes, not merely semantic hashes. It performs
exact safety CAS followed by exact fixed settings CAS, each with binary
name/autoload/before-value predicates and exactly one affected row. Both expected
tuples are read back under locks, then explicit COMMIT acknowledgement, same
physical session/idle state, post-commit exact readback and renewed auth/close
are required for private success. There is no arbitrary SQL/callback under locks.
The safety row cannot survive alone after a definite second-write failure.

One attempt; no retries, compensation, reconnect, new command, refreshed deadline
or automatic abandonment. Definite pre-commit failure confirms owned rollback or
poisons/closes. A prior committed begin stays pending. An unknown COMMIT poisons
without calling rollback as a no-effect certificate. Post-commit authorization
failure withholds success but cannot undo or replay the durable pair.

Receipt resolution requires a **fresh receipt_read** form/window and its separate
nonce action, with genuine authorization before protected reads. A new private
native transaction locks safety first/settings second before interpreting even
absence. It explicitly terminates the transaction, checks idle state, renews
auth, validates the full retained real-domain chain outside locks, renews auth
again and closes before returning private support-safe facts. It performs zero
UPDATEs. A blocked/unacknowledged barrier is unavailable, never absence proof.

Historical completed/begin-only/unresolved/domain-conflict facts are separate
from matching/superseded current raw target bytes. Internal completion IDs or
upgrade IDs cannot masquerade as authenticated begin operations. Missing history,
restore, pruning, wrong domain or unsupported state never certifies rollback/no
effect. Matching bytes do not certify cache convergence or effective scan stop.

## Proof limits and next gate

The missing-COMMIT-ack branches are **protocol simulations on real committed and
uncommitted sessions**, not genuine dropped-wire acknowledgements. Real owned
disconnect before COMMIT does not prove COMMIT wire-loss handling. No server
crash/power-loss/failover/deadlock/DDL/TLS/proxy/socket or all-platform proof.
Synthetic closed schema-6/8 genesis is not authenticated upgrade provenance.
Revocation during the critical section is not atomically excluded. Fresh barrier
facts can be superseded after release; they are historical/non-authorizing.

No cache invalidation, application-facing API, all-writer coordination, scan/queue
stop, producer/consumer lifecycle admission, durable unresolved-command registry,
restore/downgrade/uninstall admission or old-binary exclusion is enabled/proven.
No authenticated grants, activation, schedule apply/rollback or production wiring.
SQL transaction rollback in disposable proof is not schedule rollback execution.

Implementation-plan progress: the V2.3 native paired storage/resolution gap now
has real owned atomicity and contention evidence, not maintenance-only churn.

Scan-Stop Lifecycle Admission Integration Design**. Map cache publication,
all settings writers and scan producers/consumers, unknown-command fencing and
restore/old-binary boundaries before approving runtime integration. Design-only;
keep actual application state, wiring, grants, activation and rollback disabled.
