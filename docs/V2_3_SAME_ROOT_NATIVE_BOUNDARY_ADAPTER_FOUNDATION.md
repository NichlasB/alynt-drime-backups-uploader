## Implemented adapter ordering and ownership

1. Separate consumed/reentry root, owned role/query fences and original core/
   actor/cookie/clock. Supported-profile metadata precedes first intent check;
   protected payload capture and owned session creation follow authorization.
2. New fixed capture boundary calls original admission_capture: two equal bounded
   sweeps/20 projections, not atomicity. Original factory handle is retained
   privately, detached and closed before construction/nonce callbacks. False or
   throwing close overrides a frame; no second close in outer finally.
3. Reuse registration construction, full candidate and own minimal origin/complete
   historical plus ten reserved identities BEFORE writer setup/possible DML.
   Full built form/pin remains only on the immediate private root stack.
4. Original owned writer factory/outcome session, exact metadata and idle setup;
   then BOTH original mutation nonce domains, actor/cookie/core/physical/budget
   and exact full pin checked again immediately before original transaction.
5. Original safety-first compare/single ledger CAS/readback/COMMIT and raw sent/
   acknowledgement capture. No auth/parser/WordPress callbacks under locks. False
   or throw is not a successful commit; unchanged sealed qualification follows
   actual close. Current guards remain null/unperformed in that qualification.
6. Terminal admission receipt is independent of erased outcome. Only committed/
   uncertain history plus confirmed client close reaches a new diagnostic intent.
   Full stack construction/pin and writer fields/outcome are erased BEFORE read
   callbacks. No admission factory/cleanup capture restarts after erasure.
7. Original same-request mutation guard, separate small/full read domains and
   distinct lookup identity. Reuse guarded build and stage/claim DATA consumption;
   then NEW idle barrier/session metadata and BOTH read checks again before BEGIN.
   Only own typed envelope/original read start reaches unchanged barrier_capture.
8. Original ten safety-first projections/two metadata/two zero-DML inspections,
   acknowledged COMMIT and idle checks, followed by separate confirmed close.
   This is READ WRITE locking SQL with zero DML, not SQL READ ONLY. Strict counts
   and release precede consumed DATA parsing, fresh post-close guards and native-
   path result qualification. Candidate bytes cannot manufacture native evidence.
9. Finally settles only the current resource phase once, checks receipt/slot/
   budget state, erases private DATA/borrowed slots, restores exact owned filters
   and previous handler. Cleanup failure/reentry overrides a computed result.

Capture/admission/barrier each have a private terminal close observation: null
means never opened, false is permanently unavailable, true is actual API close
confirmation at this source layer. Null handle slots alone never imply success.
Admission cleanup delegates to original outcome-session finish; barrier cleanup
delegates to the separate original native finish, checking the original owned
handle, acknowledged barrier phase, preserved phase and empty slots. Unknown
BEGIN/COMMIT/rollback is poisoned, not retried or probed for favorable history.
Known owned transaction rollback follows existing policy. Borrowed auth handle
is never configured, closed or exported. Partial setup is also cleaned once.

Fixed maximum40 admission projections +10 barrier projections, one ledger CAS,
one observation, admission10s/read10s inside original20s, nonregressing UTC and
intent expiry. These are acceptance limits, NOT hard cancellation. Native profile
remains loopback MariaDB10.6/mysqli/mysqlnd, existing timeouts3s/5s/2s/3s and exact
schema/metadata visibility. No actual compatibility/privilege experiment ran.

Result remains nine fields: only the actual adapter pipeline can set its existing
barrier_verified/candidate_only distinction, and change candidate absence to
not_observed_at_barrier. Authentication/closure/retry/storage/dispatch/execution
stay false. Synthetic native API labels in tests are not a real barrier. Client
release is not server quiescence; absence never certifies cancellation/safe retry.
